## 摘要
數據集將 CommonCrawl 與 14 個高品質來源合併後，執行全域去重，並依重複次數分為 `1-1`、`2-5`、`6-10` 等區間資料夾。訓練時可直接依區間抽樣來控制重複語料比例，無需每次重新跑去重流程，藉此避免模型過擬合高頻資料。`dm_math` 等子集因 HuggingFace 單資料夾限於 10,000 檔案，會強制拆分為 `full_data_1` 與 `full_data_2`，需透過 `manifest.json` 統一索引以避免漏檔。讀取 JSON Schema 時應優先檢查 `dup_signals.dup_doc_count` 判斷全局重複量，並搭配 `dup_dump_count` 評估來源多樣性。計算 `dup_dump_count` 時必須排除標記為 `unknown` 的紀錄，以確保統計基準與有完整來源記錄的檔案一致。針對 `unknown` 來源的文件，其 `dup_details` 會顯示未知分佈，此為早期未紀錄 dump 來源的工程妥協，下游分析時需特別標記處理。

## 問答
**Q: 「全域去重」是甚麼，高品質語料又是甚麼**
全域去重指將 99 份 CommonCrawl 快照與 14 個高品質來源合併後，跨所有來源比對並移除重複段落，避免模型過擬合特定來源或造成訓練資料洩漏。高品質語料則指經過提取、過濾、去重與移除個資後，保留資訊密度高且無廣告或機器翻譯噪音的文本，如學術論文與法律文件。

**Q: 講解一下這個數據集的結構以及訓練邏輯以及 Common Crawl 的 JSON Schema 與去重訊號（dup_signals）的設計細節**
數據集依重複次數分桶存放於 `1-1` 至 `1001-inf` 等區間資料夾，訓練時直接按桶抽樣以精確控制重複語料混入比例。Common Crawl 的 JSON Schema 包含 `text`、`meta` 與 `subset`，其中 `meta` 內建 `quality_signals` 與 `dup_signals`。`dup_signals` 使用 `dup_doc_count` 記錄全局重複總量，並用 `dup_dump_count` 統計重複副本來自的 dump 來源數量。

**Q: dm_math這又是甚麼，分類數量的依據?**
`dm_math` 為數據集中的數學領域子集，其分類並非基於重複數量，而是因 HuggingFace Repository 限制單資料夾最多存放 10,000 個檔案。為符合平台規範，資料被強制拆分為 `full_data_1` 與 `full_data_2` 子資料夾，路徑編號僅代表檔案順序與內容分類無關。

**Q: llm360網頁底下提供的K2-65B,Crystal-7B,Amber-7B這幾個模型是做甚麼用的，訓練的資料集是我上面丟的那個嗎**
提供的原始文本內容完全未提及 K2-65B、Crystal-7B 或 Amber-7B 等模型名稱。文本僅聚焦於 TxT360 的數據處理流程、目錄結構與 JSON Schema 設計，未涉及後續模型訓練或應用層級資訊。

## 模型補充問答
**Q: 區間分桶的訓練對應：目錄用 2-5、6-10 這類區間而非精確數字，這是否為了配合訓練時動態調整重複比例的抽樣機制？如果是，抽樣時如何處理跨區間的邊界文件（例如重複次數剛好是 6 的文件）？**
是的，區間分桶旨在降低目錄管理成本並避免資料夾數量線性爆炸。訓練框架會將每個區間視為一個頻次層級，直接按比例抽樣或調整 loss，邊界文件會依其實際重複次數歸入對應區間，無需額外處理。

**Q: unknown 對統計的影響：文本明確寫 dup_dump_count 會排除 unknown 計算。這是否代表該部分文件的元資料不完整？**
是的，這代表部分文件的元資料確實不完整。早期去重階段未紀錄每個副本的 dump 來源，為節省成本未重跑流程，故統一標為 unknown。排除它可避免虛高或失真，確保下游分析數據分佈與評估資料多樣性時得到正確統計。

**Q: dup_signals 裡為什麼要同時保留 dup_doc_count 和 dup_dump_count？它們在訓練或數據篩選時各自扮演什麼角色？**
`dup_doc_count` 負責記錄全局重複總量，直接對應按重複數分桶的邏輯，用於訓練時控制高頻語料混入比例。`dup_dump_count` 則負責統計重複副本來自的 dump 來源數量，用於評估數據來源廣度與多樣性，兩者分開保留可讓下游在訓練控管與品質評估時各有依據且互不干擾。

**Q: dm_math 因 HF 平台限制被強行拆成 full_data_1/ 與 full_data_2/。這種結構扭曲在後續做跨資料夾統計或訓練抽樣時，會帶來什麼隱性陷阱？開發者通常怎麼補救？**
隱性陷阱在於訓練 pipeline 若用 glob 或目錄遍歷讀檔極易漏檔，路徑深度不同會導致抽樣權重失衡，且未來更新時易造成離線與線上資料分佈不一致。補救做法是在根目錄放置 manifest.json 或 filelist.txt 集中管理子路徑，並讓訓練框架改讀集中索引而非直接掃描目錄。
